WebGLRenderer — Rendering Techniques Guide

A comprehensive guide to every rendering technique the WebGLRenderer uses to turn a Scene into pixels: how geometry lives on the GPU, how a frame is assembled pass by pass, the catalogue of draw techniques (triangles / lines / points / generic), and the post-process and lighting effect pipelines (SAO, shadows, HDR, bloom, FXAA, IBL, sky, grid, section caps).

This document is an architecture reference for engineers working inside the renderer. It assumes WebGL2 and familiarity with the GPU pipeline.

1. Big picture

The renderer is built around three ideas:

  • GPU-resident geometry. Vertex data, indices, per-mesh attributes, transforms and per-object flags are all stored in data textures and read in shaders via texelFetch(). Draw calls carry almost no per-mesh CPU overhead — a whole batch is drawn with gl.drawArrays, and the vertex shader reconstructs each vertex by indexing into textures from gl_VertexID.

  • Composable draw techniques. A DrawTechnique is one compiled shader program plus the GL state and uniform/texture binding logic for one rendering job (lit colour, edges, silhouette, picking, snapping, shadow depth, …). Concrete techniques are permutations along orthogonal capability axes (normals, UVs, triplanar, edges, thick, log-depth, snap, picking) and are lazily compiled — only the variants a scene actually needs exist.

  • A fixed, ordered pass pipeline. Each frame, batches are classified into render bins, effect pre-passes (SAO, shadows, IBL) are run, then opaque → caps → edges → transparent → silhouettes are drawn, and finally the HDR buffer is composited through bloom → tonemap → FXAA and the overlay is drawn on top.

Scene/View change
   │
   ▼
GPUMemoryManager.uploadChanges()         ← stage transform/colour/visibility into data textures
   │
   ▼
RenderManager.render()
   ├─ classify batches → 19 render bins
   ├─ _renderScene()
   │    sky / grid → IBL prefilter → SAO pass → shadow passes

   │    → transparent → highlighted/selected silhouettes
   ├─ PostProcessChain.composite()       ← bloom → tonemap → FXAA

Key files: WebGLRenderer.ts (public entry / viewer attachment), internal/renderManager/RenderManager.ts (per-view frame orchestration), internal/drawOps/DrawTechnique.ts (technique base class — the single biggest file and the heart of the shader machinery).

2. Geometry on the GPU — data textures vs VBOs

The renderer has two geometry-storage strategies. The data-texture path is primary; the VBO path (internal/gpuMemoryManager/vbos/) is a fallback for cases where buffer storage is preferable.

2.1 Data textures

Instead of vertex attributes bound through vertexAttribPointer, geometry is uploaded as textures and fetched per-vertex in the shader. This lets the renderer update a single mesh's colour/visibility/transform with a small texSubImage2D instead of re-uploading buffers, and lets one drawArrays span an entire batch.

Texture Format Stores Notes
VertexPositionTexture RGB16UI Quantized vertex positions uint16 + per-geometry dequant range
VertexColorTexture RGBA8UI Per-vertex colour
VertexNormalTexture RG16UI Per-vertex normals octahedral-encoded; only when hasNormals
VertexUVTexture RG (UI/F) Per-vertex UVs only when hasUVs
IndexTexture / EdgeIndexTexture R32UI Triangle / edge indices edge buffer = real geometric edges only
PrimitiveMeshIndexTexture RGBA32UI primitive → (meshIndex, primOffset) drives per-vertex mesh lookup & visibility packing
MeshAttributeTexture RGBA32UI ×5 texels/mesh material flags, atlas UV transforms, line/hatch slots view-invariant
MeshViewAttributeTexture RGBA8UI ×2 texels/mesh/view colour, opacity, pickable, clippable view-dependent
MeshMatrixTexture RGBA32F ×4 texels per-mesh RTC modelling matrices
viewTileCameraMatrixTexture / viewTilePickMatrixTexture RGBA32F ×4 per-tile world→view matrices RTC, per view
GeometryQuantRangeTexture RGBA32F ×2 texels dequant offset + scale world = quant * scale + offset
TextureAtlas (×5) RGBA8 sRGB / linear shelf-packed PBR maps (albedo, MR, normal, emissive, occlusion) per-mesh AtlasTransform; untextured meshes collapse to a white texel
LinePatternTexture / HatchPatternTexture / PolylineCumDistTexture RGBA8 / R32F dash patterns, hatch fills, polyline arc-length

Quantization. Positions are stored as 16-bit unsigned integers normalized into a per-geometry range, halving position memory vs float32 and decoded in-shader from GeometryQuantRangeTexture. Normals use octahedral RG16UI; colours/opacity/flags pack into uint8 channels.

RTC (relative-to-center) tiling. Large scenes are partitioned into tiles; vertex positions are stored relative to each tile's centre, and a per-tile view matrix (MatrixTexture) brings them into view space. This keeps shader coordinates small and avoids float32 jitter for geometry far from the world origin. See internal/gpuMemoryManager/GPUTileManager.ts and internal/gpuMemoryManager/dataTextures/index.md.

2.2 In the shader

The vertex shader resolves a vertex purely from gl_VertexID:

gl_VertexID ─▶ primitive index ─▶ (meshIndex, primOffset)   [PrimitiveMeshIndexTexture]
                                 ─▶ vertex index            [Index/EdgeIndex texture]
                                 ─▶ quantized position       [VertexPositionTexture]
                                 ─▶ dequant via range        [GeometryQuantRangeTexture]
                                 ─▶ mesh matrix + tile view  [Mesh/MatrixTexture]
                                 ─▶ gl_Position

3. Per-object state & flags

State is split CPU↔GPU and synchronized on uploadChanges().

  • CPU (internal/meshManager/RendererMesh.ts): a per-view ViewStateBits byte — Colorizing, ColoringOpacity, Transparent, ObjectVisible, MeshVisible.
  • GPU visibility packing (PrimitiveMeshIndexTexture): each mesh's primitives form a portion tagged with objectVisible, meshVisible and a renderPass. Only portions that are both object- and mesh-visible are packed into the contiguous primitive ranges that get drawn — invisible meshes contribute zero primitives without being deallocated.
  • GPU display props (MeshViewAttributeTexture): per-view colour, opacity, pickable, clippable.

Each batch keeps, per view, a map of renderPass → primitive range, so one batch can contribute to several passes (e.g. OPAQUE and HIGHLIGHTED) and each pass draws only its own range.

4. The frame lifecycle

Driven by RenderManager.render() → _beginFrame() → _classifyBatches() → _renderScene() → _endFrame() → PostProcessChain.composite() → _renderOverlay().

_renderScene() runs in this strict order:

  1. Clear colour + depth.
  2. Environment — SkyRenderer, then InfiniteGridRenderer (if enabled).
  3. IBL prefilter — refresh per-view irradiance / prefiltered-specular cubemaps if HDR is active.
  4. SAO pre-pass — depth → occlusion (+ optional blur) into the SAO FBO, if any SAO batches exist.
  5. Shadow pre-passes — render caster depth into each CSM cascade FBO, if any shadow batches exist.
  6. Rebind scene target and restore GL state.
  7. Opaque colour — four bins: normalDrawOpaque, normalDrawSAO, normalDrawShadow, normalDrawSAOShadow.
  8. Section-plane caps — stencil-masked cap quads.
  9. Unbind shadow maps.
  10. Opaque edges (thin or thick per edgeWidth).
  11. Opaque x-ray silhouettes + edges.
  12. Transparent block — BLEND on, depth-write off: x-ray edges/fills, then normal edges/fills.
  13. Depth clear (for "always-on-top" emphasis).
  14. Opaque highlighted/selected silhouette fills + edges (depth-cleared so they sit on top).
  15. Transparent highlighted/selected silhouettes + edges.

Then composite() resolves the HDR buffer through bloom → tonemap → FXAA to the canvas, and _renderOverlay() draws the overlay bin (gizmos/HUD) last so it is never occluded.

5. Render bins & classification

internal/renderManager/RenderBinClassifier.ts sorts every batch, each frame, into 19 render bins. Binning exists so that GL state (depth-write, blend, polygon offset), effect requirements (SAO/shadow pre-passes), and draw order (opaque before transparent; emphasis after a depth clear) are correct and set once per bin rather than per mesh.

  • Opaque colour (split by effect support): normalDrawOpaque, normalDrawSAO, normalDrawShadow, normalDrawSAOShadow.
  • Edges: normalEdgesOpaque, normalEdgesTransparent.
  • Transparent fill: normalFillTransparent.
  • X-ray: xrayedSilhouette{Opaque,Transparent}, xrayEdges{Opaque,Transparent}.
  • Highlighted: highlightedSilhouette{Opaque,Transparent}, highlightedEdges{Opaque,Transparent}.
  • Selected: selectedSilhouette{Opaque,Transparent}, selectedEdges{Opaque,Transparent}.

Classification queries each batch's per-pass bitfield (hasMeshesInRenderPass(view, pass)) and routes:

  • Opaque default-bin batches → SAO/shadow variant by which effects are enabled (overlay-bin batches always go to plain normalDrawOpaque, skipping effects).
  • Transparent → normalFillTransparent.
  • X-ray / highlighted / selected → opaque vs transparent silhouette bin by the effect material's fillAlpha; edges by edgeAlpha.

6. Render passes

internal/renderManager/RENDER_PASSES.ts:

Pass Value Purpose
NOT_RENDERED 0 suppress
OPAQUE 1 lit opaque geometry
TRANSPARENT 2 blended geometry
HIGHLIGHTED 3 highlight silhouette (fill + edges)
SELECTED 4 selection silhouette
XRAYED 5 x-ray silhouette (see-through emphasis)
PICK 6 write batch/mesh IDs + depth to pick buffer
SNAP_INIT 7 rasterize surfaces into the snap FBO to seed depth
SNAP 8 rasterize vertices/edges, depth-tested, write view positions

(SHADOW_DEPTH is not a RENDER_PASSES value — the shadow depth technique is dispatched directly by ShadowPipeline, once per cascade.)

7. The DrawTechnique abstraction

internal/drawOps/DrawTechnique.ts is the abstract base for every technique. A technique = one compiled WebGLProgram + its GL-state and uniform/texture binding logic for one rendering job.

7.1 Lifecycle

  • construct with capability flags (see below).
  • init() → buildVertexShader() + buildFragmentShader() assemble GLSL, compile, link, and cache uniform/sampler locations.
  • webglContextRestored() recompiles after context loss.
  • drawBatch() / drawMesh() → _bind() → _draw() bind the program (skipping the rebind when it's already current via renderContext.lastProgramId), upload pass uniforms, bind data textures, and issue the draw call.
  • destroy() releases GPU resources.

7.2 Shader assembly (template method)

Subclasses don't write monolithic GLSL — they compose it from reusable snippets that append to _vertSrcBuf / _fragSrcBuf. Two kinds:

  • Declarations (vs*Declarations() / fs*Declarations()) — emit uniforms, samplers, varyings, helper functions, run early.
  • Logic (vs*Logic() / fs*Logic()) — emit main() body code, in a deliberate order.

Representative building blocks: vsCommonDeclarations (data-texture samplers + mesh lookup), vsLambertShadingDeclarations/Logic (normals/PBR/lighting), vsSlicingDeclarations/Logic & fsSlicingLogic (section planes), vsSnapDeclarations/Logic & fsSnapLogic, vsThickLineMain / fsThickLineLogic (quad expansion + SDF), vs/fsSilhouetteLogic, vs/fsEdgeFadeLogic, fsDrawSAOLogic, fsDrawShadowLogic, fsPickMeshLogic, fsOutputColor (premultiplied alpha: outColor = vec4(color.rgb * color.a, color.a)).

7.3 Capability axes (constructor flags)

{
  edges?:      boolean,            // read edge-index buffer, use edge-material colours
  picking?:    boolean,            // MRT: batch/mesh IDs + depth (mutually exclusive w/ edges)
  snap?:       0 | 1 | 2 | 3,      // 0 normal · 1 vertex-snap · 2 edge-snap · 3 snap-init
  hasNormals?: boolean,            // sample per-vertex normals → smooth shading + PBR
  hasUVs?:     boolean,            // sample per-vertex UVs → texture atlases
  triplanar?:  boolean,            // world-space projection (mutually exclusive w/ hasUVs)
  thickLines?: boolean,            // 6 verts/segment quad expansion (edges/lines)
  logDepth?:   boolean             // logarithmic depth write (camera-visible passes only)
}

Flat vs smooth shading: when hasNormals is false the fragment shader derives a flat face normal from screen-space derivatives (cross(dFdx(viewPos), dFdy(viewPos))); when true it samples and interpolates octahedral per-vertex normals. Both feed the same Lambert/Cook-Torrance BRDF.

7.4 Draw dispatch

_draw() selects the GL primitive from primitive-type × snap × edges × thickLines, e.g. triangles → gl.TRIANGLES; thin edges / edge-snap → gl.LINES; vertex-snap → gl.POINTS; thick edges/lines → gl.TRIANGLES over a 6-verts-per-segment expansion. Section planes (up to 8) are packed once per frame and evaluated in the FS (dot(n, worldPos) + d ≤ 0 → discard). Optional logarithmic depth (uLogDepthCoef = 2 / log2(far + 1)) improves precision across huge depth ranges and is restricted to camera-visible passes (not pick/snap/shadow, whose read-back math needs linear depth).

7.5 Class-naming convention

<Primitive><RenderDescriptor><Modifier>Technique

RenderDescriptor ∈ {DrawColor, DrawEdgeColor, DrawSilhouette, Snap, StencilMask, ShadowDepth}; Modifier ∈ {Flat (unlit), SAO, Shadow, SAOShadow, Thick, EdgeSilhouette, SnapInit, …}. E.g. TrianglesDrawColorSAOShadowTechnique = lit triangle colour with both SAO and shadows.

8. Triangle techniques

Directory: internal/drawOps/techniques/triangles/.

8.1 Colour (lit)

  • TrianglesDrawColorTechnique — the workhorse. Lambert/Cook-Torrance shading with optional PBR atlas sampling. Compiles in a 6-way permutation over (hasNormals × {none, hasUVs, triplanar}). OPAQUE pass: no blend, depth write on. TRANSPARENT pass: premultiplied blend (ONE, ONE_MINUS_SRC_ALPHA), depth-write off.
  • TrianglesDrawColorSAOTechnique — base colour + a screen-space AO multiply (fsDrawSAOLogic) sampling the SAO occlusion texture, gated by a blend cutoff.
  • TrianglesDrawColorShadowTechnique — base colour + cascaded shadow lookup (fsDrawShadowLogic): transform to light clip space, pick a cascade by view-Z against the splits, PCF-sample the cascade map, clamp shadowed regions to an ambient floor, with slope + normal-offset bias.
  • TrianglesDrawColorSAOShadowTechnique — both, in the order Lambert → Shadow → SAO. Order matters: shadow clamps to an ambient floor that doesn't carry AO, so SAO must run last or crevice occlusion vanishes inside cast shadows.
  • TrianglesDrawColorFlatTechnique — unlit, pure vertex colour, for the overlay bin (gizmos/HUD). Deliberately omits section-plane clipping (overlay UI must never be cut) and sRGB-encodes inline because it draws after the post-process composite.

8.2 Silhouettes & edges

  • TrianglesDrawSilhouetteTechnique — solid-colour filled silhouette; colour comes from the per-pass uSilhouetteColor (highlight / selected / xray fill colour).
  • TrianglesDrawEdgeColorTechnique — thin (gl.LINES) edges from the edge-index buffer, with distance-based edge fade (uEdgeFadeRange). The preceding triangle pass uses polygon offset so edges win depth ties.
  • TrianglesDrawEdgeColorThickTechnique — edges >1px, expanded to screen-space quads (6 verts/edge) with a rounded-rect SDF for antialiasing; width from uLineWidth.
  • TrianglesDrawEdgeSilhouetteTechnique — same as edge-colour but coloured from the per-pass emphasis material's edgeColor (HIGHLIGHTED/SELECTED/XRAYED).

8.3 Utility

  • TrianglesShadowDepthTechnique — renders depth from the light's POV into a cascade FBO; colour-mask off, depth only. Slicing is evaluated in camera space so caps still cut correctly.
  • TrianglesStencilMaskTechnique — two-pass stencil writer for section-plane caps: front-cull DECR_WRAP, back-cull INCR_WRAP, colour + depth masked off. Leaves stencil ≠ 0 where the model crosses the cap plane.
  • TrianglesSnapInitTechnique / TrianglesSnapTechnique — see Snapping.

9. Line techniques

Directory: internal/drawOps/techniques/lines/.

  • LinesDrawColorTechnique — thin hardware lines (gl.LINES, 2 verts/line). Note that many WebGL2 stacks clamp line width to 1px, which is why thick lines exist.
  • ThickLinesDrawColorTechnique — thick lines via vertex-shader quad expansion (6 verts/segment). Each segment becomes a screen-space quad: the perpendicular offset is computed in NDC×drawing-buffer pixels and scaled by clip-w so thickness is constant in pixels at any depth. Supports miter vs round joins (neighbours found via the primitive texture: same mesh + sequential offset), dash patterns (8-entry, per-mesh or global), and polyline-continuous dashing (cumulative arc-length from PolylineCumDistTexture keeps dashes phase-continuous across joints). The fragment shader evaluates a rounded-rectangle SDF for 1px-falloff antialiasing and walks the dash pattern.
  • ThickLinesPickMeshTechnique — same quad expansion, but writes pick MRTs; a binary in/out SDF test prevents cap corners from poisoning neighbouring pick pixels, so the whole thick body is pickable (not just the 1px centreline).
  • LinesSnapTechnique — snap against true line geometry: snap=1 draws endpoints as gl.POINTS, snap=2 draws the mathematical centreline as gl.LINES, both writing view-space position to the snap FBO.

10. Point techniques

Directory: internal/drawOps/techniques/points/. One vertex per point, no index buffer.

Point size: perspective mode sets gl_PointSize = uNearPlaneHeight * pointSize / clipPos.w (clamped to a min/max); orthographic mode uses a fixed pixel size. Round points discard fragments outside the unit circle of gl_PointCoord.

  • PointsDrawColorTechnique — per-vertex coloured point clouds, premultiplied blend.
  • PointsDrawSilhouetteTechnique — highlight/select/xray overlay colour for points.
  • PointsPickDepthTechnique — writes only normalized depth (for depth-based ray queries that reconstruct world position externally).
  • PointsPickMeshDrawTechnique — writes batch/mesh IDs + packed depth to the pick MRTs.

11. Generic techniques

Directory: internal/drawOps/techniques/generic/. Geometry-type-agnostic techniques parameterized by vertsPerPrim (3 triangles / 2 lines / 1 points), so one class serves all primitive types:

  • GenericDrawSilhouetteTechnique(vertsPerPrim) — silhouette/edge overlay for any primitive; colour from uSilhouetteColor or a darkened mesh colour.
  • GenericPickMeshTechnique(vertsPerPrim) — mesh/batch ID + depth picking for any primitive (avoids per-primitive-type pick shader variants).

12. Picking

internal/pickManager/PickManager.ts + internal/webGL/WebGLPickBuffer.ts.

GPU picking renders into a tiny (1×1) framebuffer with three RGBA8 colour attachments + a depth renderbuffer:

  • attachment 0 — batch index (uint32 packed to RGBA8)
  • attachment 1 — mesh index (uint32 packed to RGBA8)
  • attachment 2 — packed normalized depth

The pick viewport is remapped so only the cursor pixel is rendered. A default-bin pass runs first; an optional overlay-bin pass then clears depth and uses depthFunc(ALWAYS) so UI gizmos win. gl.readPixels retrieves the texel; the manager unpacks the IDs to find the batch/mesh, unpacks depth, and reconstructs the 3D hit by unprojecting the cursor ray to the recovered depth. Ray-picking builds a lookAt matrix aligned to an arbitrary ray and fires through the canvas centre. Two flavours: pick-mesh (ID + position) and pick-depth (depth only).

13. Snapping

internal/snapManager/SnapManager.ts + internal/webGL/WebGLSnapBuffer.ts.

Snap-to-vertex / snap-to-edge render into a small (2·snapRadius+1)² RGBA32F framebuffer centred on the cursor:

  1. SNAP_INIT — rasterize triangle surfaces to seed depth and write view-space position with an alpha = 2.0 sentinel ("surface").
  2. SNAP — rasterize vertices (gl.POINTS) or silhouette/real edges (gl.LINES) at 1px, depth-tested against the init pass, writing vec4(viewPos, 1.0) (alpha = 1.0 = "hit").

The buffer is read back as a Float32Array; the nearest alpha == 1.0 texel to the centre wins (vertices beat edges at equal distance), and the view-space position is converted to world space via the inverse view matrix. Snapping rides the edge buffer, never triangle diagonals, so it only snaps to real geometric corners/edges.

14. Effect & post-process pipelines

Directory: internal/renderManager/. Pre-passes (SAO, shadows, IBL) publish their textures on the RenderContext so colour techniques can bind them; the post chain composites the HDR buffer to the canvas. Every fullscreen effect uses a 3-vertex gl_VertexID triangle (no VBO).

14.1 SAO — Scalable Ambient Obscurance (sao/)

Darkens crevices using screen-space depth. SAOPipeline renders eligible geometry depth into an FBO; SAOOcclusionRenderer samples that depth in a Hammersley spiral kernel, reconstructing view-space position (perspective and ortho, log-depth aware) and accumulating occlusion max(0, (dot(n, Δ) − minRes) / scaledDist − bias) / (1 + scaledDist²). SAODepthLimitedBlurRenderer does an optional separable Gaussian blur that stops at depth discontinuities to avoid halos. Output occlusion is multiplied into surface colour by the SAO draw techniques.

14.2 Shadows — Cascaded Shadow Maps (shadows/ShadowPipeline.ts)

Directional CSM. The view frustum is split into cascadeCount slices via PSSM (lambda-weighted blend of logarithmic and uniform splits). Each cascade gets a tight orthographic light-view fit, snapped to a world-space texel grid for temporal stability (no shadow crawl when panning). Caster depth renders into per-cascade FBOs (DEPTH24_STENCIL8, depth comparison enabled); light-VP matrices, depth textures and split distances are published for the shadow draw techniques, which select a cascade by view-Z and PCF-filter. Unused cascade slots alias cascade 0 so samplers always bind.

14.3 HDR (hdr/HDRRenderTarget.ts)

When EXT_color_buffer_float is available, the scene renders into an RGBA16F FBO (plus DEPTH24_STENCIL8) sized to sceneRenderWidth/Height (may exceed canvas size for supersampling), with LINEAR filtering for free bilinear downsampling. Without HDR the scene draws straight to the canvas and the post chain is a no-op.

14.4 Bloom (bloom/BloomPipeline.ts)

Kawase dual filter (Bjørge 2015). A soft-knee bright-pass prefilter (Unreal-style, with NaN/Inf sanitization and a 32.0 clamp to kill fireflies) feeds a 5-level mip pyramid: 5-tap Kawase downsample down the chain, 8-tap tent upsample with additive blend back up, then an additive composite into the HDR target.

14.5 Tonemap (hdr/TonemapPipeline.ts)

Fullscreen HDR→LDR. Applies exposure, then one of: none (identity), Reinhard (c/(c+1), mode 1), or ACES (mode 2, Stephen Hill's RRT+ODT fit clamp((c·(2.51c+0.03))/(c·(2.43c+0.59)+0.14), 0, 1)), with optional sRGB encode. Writes to the canvas (or an LDR intermediate when FXAA follows).

14.6 FXAA (fxaa/FXAAPipeline.ts)

Lottes/NVIDIA FXAA 3.x: luma edge detection (dot(rgb, (0.299,0.587,0.114))), early-out on flat regions, edge direction from corner luma gradients, span clamped to ±8px, with a 4-tap/2-tap fallback to preserve detail. Runs after tonemap, LDR→canvas.

14.7 IBL — Image-Based Lighting (ibl/)

  • BRDFLUTTexture — 256×256 split-sum BRDF integration LUT indexed by (NdotV, roughness), GGX importance-sampled (Hammersley), Schlick-GGX geometry (IBL k = α²/2), returning Fresnel (scale, bias).
  • IBLPrefilter (per view) — builds a source environment cubemap (sky or equirect, with mips), a prefiltered specular cubemap (8 roughness mips, GGX importance sampling with Krivánek-Colbert solid-angle mip selection to suppress noise on smooth metals), and a 32×32 irradiance cubemap (cosine-weighted hemisphere convolution) for diffuse.

14.8 Environment (environment/)

  • SkyRenderer — fullscreen procedural three-band gradient (ground/horizon/zenith) plus sun disc + glow + horizon haze, with translation stripped from the view matrix (RTE) for precision; ray direction reconstructed per pixel via the inverse view-projection.
  • InfiniteGridRenderer — camera-following floor grid; fwidth-based derivative antialiasing for minor/major lines and axes, with distance fade. Alpha-blended, depth-write off.

14.9 Section-plane caps (sectionPlaneCaps/CapPlaneRenderer.ts)

Two-stage capping of clipped solids. TrianglesStencilMaskTechnique writes the stencil (front-DECR / back-INCR) where the model crosses a cap plane; CapPlaneRenderer then draws a fullscreen pass gated by stencilFunc(NOTEQUAL, 0) that ray-intersects each pixel with the cap plane, union-clips against the other active planes, re-projects to write correct gl_FragDepth, and outputs the cap colour — a solid cut surface only where the model exists.

15. Feature gating — capabilities & memory configs

  • Capabilities.ts exposes WebGL2 support, max views, and texture-compression formats (ASTC/ETC/DXT/BPTC/PVRTC). HDR/bloom/FXAA/IBL effects degrade gracefully when their extensions (e.g. EXT_color_buffer_float) are absent.
  • MemoryConfigs.ts / createMemoryConfigs.ts size the GPU budgets: RTC tileSize, maxViews, maxTiles, and per-batch limits (maxBatchVertices/Indices/Geometries/ Meshes/Prims). createMemoryConfigs() picks a device profile (low/medium/high), computes per-element byte costs, splits a gross budget ~70/20/10 across geometry / mesh metadata / tiles, derives clamped limits, then merges user overrides.

16. WebGL abstractions

internal/webGL/ is a thin typed layer over raw GL:

WebGLProgram / WebGLShader (compile/link, attribute/uniform/sampler maps), WebGLAttribute, WebGLArrayBuf, WebGLTexture / WebGLAbstractTexture, WebGLRenderBuffer, WebGLSampler (WebGL2 sampler objects), WebGLContextProvider (context loss/restore). Specialized: WebGLPickBuffer (1×1 ×3-MRT pick FBO), WebGLSnapBuffer (+ a cache keyed by snap radius). Helpers: convertWebGLConstant, getWebGLExtension, canvas2image.

The internal/inspectors/ directory provides debug overlays — GPU memory usage, render stats, tile/draw-call breakdowns, shader inspection.
